# AI_ARCHITECTURE.md — MK GitFlow

How the optional AI layer works, and the guarantees it makes. It implements
STANDARDS §10 and PRODUCT_SPEC §3.8. The AI layer is **additive**: the app builds
and every deterministic tool works with no AI configured at all.

## 1. Shape

- One dynamic route serves every capability: `POST /api/ai/<capability>`
  (`src/app/api/ai/[capability]/route.ts`). The slug is validated against a typed
  registry before any work happens; unknown slugs 404.
- The route delegates to a single shared handler
  (`src/lib/ai/server/handler.ts`) that runs the same pipeline for all
  capabilities:

  ```
  rate limit → body-size guard → JSON parse → zod validate
             → availability/auth resolve → generateObject → typed response
  ```

- Structured output only: each capability has a zod **output** schema
  (`src/lib/ai/server/output-schemas.ts`) passed to `generateObject` from the
  `ai` package (Vercel AI SDK v6). The model is forced to return exactly the
  shape the UI renders, so client and server never drift.

## 2. Capabilities

| Slug | Tier | Deterministic fallback |
|---|---|---|
| `nl-to-command` | fast | Yes — keyword match against the command reference |
| `commit-from-diff` | fast | Yes — diff heuristic + Conventional Commit builder |
| `pr-description` | quality | Yes — commits arranged into a PR template |
| `release-notes` | quality | Yes — Conventional Commits grouped into a changelog |
| `explain-error` | quality | No — honest "AI unavailable" note |
| `explain-conflict` | quality | No — honest "AI unavailable" note |
| `rebase-plan` | quality | No — honest "AI unavailable" note |
| `branch-strategy` | quality | No — honest "AI unavailable" note |
| `explain-ci-error` | quality | No — honest "AI unavailable" note |

`nl-to-command` output always carries `command`, `explanation`, `riskLevel`,
`destructiveWarning` (non-null only when destructive), `saferAlternative`, and
`undoGuidance`. In the UI, destructive results render through the shared
`CommandLine` component, whose copy button is **gated** (two-step "Copy anyway?")
so a destructive command cannot be copied until the warning is acknowledged.

## 3. Models and auth

- Gateway model strings, env-configurable so a model swap is a config change, not
  a code change (`src/lib/ai/server/models.ts`):
  - `AI_MODEL` — fast tier, default `anthropic/claude-haiku-4.5`
  - `AI_MODEL_QUALITY` — quality tier, default `anthropic/claude-sonnet-4-5`
- Auth precedence:
  1. **BYOK** — a per-request key from the `x-byok-key` header builds a one-off
     gateway via `createGateway({ apiKey })`. The key is used only for that
     request and is never stored, cached, echoed, or logged.
  2. **Server credentials** — `AI_GATEWAY_API_KEY`, or Vercel OIDC
     (`VERCEL_OIDC_TOKEN`, injected automatically on Vercel).
- If neither a BYOK key nor server credentials are present, the route
  short-circuits with an honest `unavailable` response (HTTP 503) — it never
  makes a doomed upstream call.

## 4. Honest degradation

The `/assistant` client (`src/components/assistant/`) never shows a fabricated
answer:

- On success: the result is labeled **"Generated by AI · <model>"**.
- On failure/unavailable where a deterministic fallback exists: the pure fallback
  (`src/lib/ai/fallbacks.ts`) runs in the browser and the result is labeled
  **"Generated locally (not AI)"** with a note explaining why.
- On failure where no fallback exists: an honest error message is shown, pointing
  to the deterministic tools (reference, simulator, guides).

Fallbacks are pure functions (no DOM, no network, no `ai` SDK), so they run in
the browser and under Vitest, and they are the single source of truth for local
results.

## 5. Rate limiting and quota (best-effort)

- **Server, per IP** (`src/lib/ai/server/rate-limit.ts`): an in-memory token
  bucket (8 burst, ~8/min sustained) plus a daily cap (200/day, UTC reset). This
  is per-instance and resets on redeploy/scale — a guardrail, not a billing
  control. The IP is only a map key held in memory; it is not logged.
- **Client, per browser** (`src/lib/ai/quota.ts`): a visible daily counter
  (40/day) in localStorage. It gates AI calls in the UI and drives the usage
  indicator; local fallbacks do not consume it. When exhausted, the UI emits
  `quota_reached` and offers the local fallback where one exists.

## 6. Input validation and limits

- Every capability has a zod **input** schema with per-field max lengths
  (`src/lib/ai/schemas.ts`, `INPUT_LIMITS`): short text 2k, error logs 8k,
  conflicts 20k, diffs 30k, commit lists 20k, CI logs 20k characters.
- The route rejects bodies over 64 KB before parsing, then re-validates the
  parsed body (never trust the client). The browser validates with the same
  schemas for fast feedback.

## 7. Privacy

- **No content logging.** There are no logging calls on any request path in the
  handler; request content is used to build the prompt and then discarded.
- **No server-side storage** of request or response content.
- **BYOK** travels only in the `x-byok-key` header, is used transiently, and is
  never stored server-side or included in analytics. It is structurally
  impossible for it to arrive in a request body (no schema field accepts it).
- **Analytics** (`ai_started` / `ai_completed` / `ai_failed` / `quota_reached`)
  carry only the capability slug and a coarse reason code — never user text,
  model output, or keys.
- **Prompt-injection hardening**: user content is wrapped in `<user_data>` fences
  and the system prompt instructs the model to treat fenced content as data to
  analyze, not instructions to follow.

## 8. Error taxonomy

Responses always use the typed envelope in `src/lib/ai/types.ts`. Error codes are
coarse and messages fixed, so nothing about the upstream or the input leaks:

| Code | HTTP | Meaning |
|---|---|---|
| `invalid-input` | 400 | Body failed validation or was too large |
| `rate-limited` | 429 | Token bucket or upstream 429 |
| `quota-exceeded` | 429 | Daily cap reached |
| `unavailable` | 503 | No credentials, or credentials rejected (401/403) |
| `cancelled` | 499 | Client aborted the request |
| `upstream-error` | 502 | Gateway/model error |
| `bad-output` | 502 | Model output didn't fit the schema |

## 9. Cancellation

The client passes an `AbortSignal` (Cancel button); the route forwards
`request.signal` to `generateObject`, so an aborted request stops server work.
